# 信源验证清单

## 6 项必验清单

一个信源验证通过，必须同时满足以下 6 项：

### 1. 能取到
- URL/参数/字段索引跑通
- 返回数据非空
- 用 `probe_source.py --source <name> --code <code>` 验证连通性

### 2. 单位正确
- 实测验证：取到的数值是什么单位？
- 元 / 亿元 / 万元？
- 手 / 股 / 万手？
- % 还是小数？
- **不要假设单位**，从返回数据实测确认

### 3. 语义正确
- 与第二信源交叉对比，偏差在合理范围内
- 用 `probe_source.py --cross --code <code> --field <field>` 做多源验证
- 偏差阈值：收盘价 < 0.01，涨跌幅 < 0.05，换手率 < 0.1
- **同名字段不同源可能定义不同**（如换手率分母可能是流通股本 vs 总股本）

### 4. 更新节奏明确
- 何时可得？T日16:00还是T+1日9:00？
- 交易日内实时更新还是收盘后一次性更新？
- 写入 registry 的 `available_after` 字段
- **这决定 collector 的定时任务时间**

### 5. 历史可回溯
- 要不要回填历史数据？
- 能回溯多远？（腾讯K线最多2000条日K线）
- 写入 registry 的 `backfill_available` 字段

### 6. 边界行为
最容易忽略但生产中最容易出问题：

| 边界场景 | 需要确认 |
|---------|---------|
| 停牌日 | 返回什么？空值？重复前值？还是该日不返回？ |
| 除权除息日 | 数值是否自动调整？还是需要手动处理？ |
| 涨跌停 | 成交量可能为0，换手率/量比可能异常 |
| 新股上市首日 | 无前日数据，涨跌额/涨跌%基准是什么？ |
| 节假日 | 非交易日是否返回数据？ |
| 港/美股 | 字段索引是否与A股一致？单位是否不同？ |

## 验证方法

### 收盘价
- 腾讯K线内嵌qt[3] vs 腾讯实时qt[3] vs 新浪close vs K线历史row[2]
- 4源一致才能确认

### 涨跌额/涨跌%
- 用收盘价和前日收盘价重算验证
- 涨跌额 = 收盘价 - 前收
- 涨跌% = 涨跌额 / 前收 × 100
- 除权日需用调整后前收

### MACD值
- 用K线重算与已存储值比对
- check_integrity.py（属 stock-data-collector skill）自动执行

### 成交额
- 腾讯qt[35] 格式为 "万/亿/元"，取第3部分为元
- K线行第10列（索引9）也可能含成交额
- 两源比对

## 交叉验证规则

- **至少2源一致**才能确认数据正确
- **3源不一致**时：标记为存疑，询问用户
- **接口超时**不算数据不一致，换源重试

## 信源验证产出

验证完成后，registry 条目的 sources 字段应包含：

```json
"sources": [
  {
    "name": "东财个股北向",
    "url_template": "https://push2his.eastmoney.com/...",
    "field_index": 5,
    "verified": true,
    "verified_date": "2026-08-16",
    "notes": "T日16:30后可用，停牌日返回空值"
  },
  {
    "name": "新浪北向",
    "url_template": "http://hq.sinajs.cn/...",
    "field_index": 3,
    "verified": true,
    "verified_date": "2026-08-16",
    "notes": "与东财偏差<0.01"
  }
]
```

`verified: true` 表示已通过全部 6 项验证。`notes` 记录边界行为等关键信息。
